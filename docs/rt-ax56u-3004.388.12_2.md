# RT-AX56U: unofficial 3004.388.12_2 compatibility port

> [!WARNING]
> **UNOFFICIAL — USE AT YOUR OWN RISK.** This port is not maintained, approved,
> or endorsed by Asuswrt-Merlin or ASUS. Incorrect firmware or flashing methods
> can brick a router, erase settings, or disrupt a network. Safe flashing,
> complete functionality, security parity, and successful recovery are not guaranteed.

## Source identity

- Upstream: [RMerl/asuswrt-merlin.ng](https://github.com/RMerl/asuswrt-merlin.ng).
- Base tag: `3004.388.12_2`.
- Base commit: `433fc608f5fc1689f3d3c3ab5cd2a7d57102260f`.
- Annotated tag object: `5ac52cf6260d5bd94e7b9796382d0e3f1356dafc`.
- Local build suffix: `2-ax56u1`; this is not an official Merlin release number.
- Target: RT-AX56U, profile `947622GW`, BCM47622/ARM and NAND pure-UBI.

The source retains upstream's AX56U-specific prebuilds. The 44 RC, 16 shared,
four HTTPD and one libwebapi model prebuilds used in the tested build match the
upstream tag; no replacement proprietary objects or foreign-model binaries are
introduced by this port. Generated build outputs and local/private files are
not part of these changes. Existing upstream license and copyright notices remain.

## Changes

- Add AX56U-only guards around unavailable newer private APIs and use the
  retained S46 mapping signatures. Other router models retain their code paths.
- Retain legacy ASD because an AX56U ASD 2.1 component is unavailable.
- Use the real legacy `ASUS_EULA` consent state for setup, DDNS and account
  features, with explicit disclosure, read-back after saves, retry handling and
  restored withdrawal controls. Do not fabricate PPv2 consent or timestamps.
- Export the legacy consent gate needed by the shipped notification daemon.
- Hide the unsupported security-update switch and make the unavailable mesh
  update command return an explicit error rather than silent success.
- Add source-owned QoS/certificate-input validators and restore the observed
  manual-firmware-page capability restriction. See the test documentation for
  the exact scope and private-hook evidence.
- Keep shipped Broadcom event-daemon prebuilts when cleaning; they are build
  inputs, not generated executables that can be rebuilt from this GPL tree.

## Compatibility limitations

This is a compatibility port, not a complete implementation of every private
12_2 feature or security mechanism. PPv2-only configuration upload remains
fail-closed. Newer private NVRAM audit, scanning/privacy initialization,
ACS-management, band-check and memory-diagnostic hooks are unavailable. Ordinary
ACS still uses the retained daemon. AiMesh, all ISP-specific modes, all VPN/QoS
combinations and recovery behavior are not comprehensively qualified.

Legacy consent withdrawal retains the baseline Internet requirement for DDNS
unregistration. A remote timeout is reported separately from local revocation.
Consumer shutdown and persistence need hardware validation beyond host mocks.

## Building

Use a compatible upstream legacy build environment and its licensed AX HND
toolchain. The tested command used Ubuntu 20.04, GCC 5.5/glibc 2.26/binutils
2.28.1, `makeinfo` (from `texinfo`), and `libltdl-dev` in addition to the upstream
build dependencies. This is the command used in that prepared environment,
not a complete from-scratch dependency-installation recipe:

```sh
cd release/src-rt-5.02axhnd.675x
toolchain=/opt/toolchains/crosstools-arm-gcc-5.5-linux-4.1-glibc-2.26-binutils-2.28.1
export LD_LIBRARY_PATH="$toolchain/lib:$toolchain/usr/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
make -j1 rt-ax56u EXTENDNO=2-ax56u1
```

Images are generated under `targets/947622GW/`. Vendor clean rules still have
optional/missing-target diagnostics; a build exit status alone is not sufficient
validation. Do not commit the generated images, logs, certificates or caches.

## The two image formats

- `RT-AX56U_3004_388.12_2-ax56u1_pureubi.w` contains the firmware UBI payload,
  including the kernel, root filesystem and boot filesystem/RAM-stage CFE.
- `RT-AX56U_3004_388.12_2-ax56u1_cferom_pureubi.w` adds a 1 MiB raw CFE-ROM
  boot region before the same UBI payload. Its format/checksum footer also differs.

The CFEROM variant is not a routine-upgrade recommendation. Depending on the
flashing method, its extra region can affect the bootloader. The filesystem-only
variant is not automatically approved for every updater either. Confirm the
exact supported image format and procedure before flashing. No universal
installation/recovery procedure is asserted here.

## Current-version ASUS image tag

Release preparation found that the vendor AX56U host `addvtoken` executable
embedded stale extension `24353`, while the packaged runtime exports
`3.0.0.4 / 388.12 / 2-ax56u1`. For AX56U only, the host-tool make rule now
installs the source-owned `ax56u_addvtoken.py` adapter. It retains the unchanged
model-specific vendor writer for WFI packing, validates that output, reads the
current generated version header, replaces the ASUS version fields, and
recomputes the whole-image CRC. Python 3 is an additional host dependency.
Other models retain their original packaging rule.

The legacy tag has integer-only build and extension fields. Its decimal-prefix
projection is `3.0.0.4 / 388 / 2`; both the 16-bit and 32-bit extension fields
are `2`. The full runtime `388.12 / 2-ax56u1` remains unchanged in the firmware.
The image auditor now rejects a tail that differs from the packaged runtime's
numeric projection; it does not trust the image filename as version evidence.

Both image formats were regenerated from the preserved raw build payloads,
without recompiling target code or changing the kernel, filesystem contents,
vendor WFI flags, or CFEROM prefix. Previously tested images were preserved.
The corrected images require a new device retest: earlier maintainer reports
apply to the prior image checksums, not to these newly tagged artifacts.
Host packaging checks and offline audits are not updater acceptance or flash
safety certification. No router is contacted or flashed by these tools.

The 2026-10-24 corrected images have these SHA-256 checksums:

```text
029e80d6daff1c631617513b24820c8a58ed9bb46664e5f5e6a37a91b334c71d  RT-AX56U_3004_388.12_2-ax56u1_pureubi.w
0624529b6bb2586bd9d5c1bf876e426d032494489575f9ab1862b5367cbf09db  RT-AX56U_3004_388.12_2-ax56u1_cferom_pureubi.w
```

Each differs from its previous image by eight bytes covering only the two
extension fields and WFI CRC. The pure-UBI candidate remains 75,628,564 bytes;
the CFEROM candidate remains 76,677,140 bytes. Host integration, UI/localization,
portable validation and ASan/UBSan tests, eleven synthetic packaging tests, and
both image audits passed. Runtime checks covered 763 ELF files, strong-symbol
closure for 257 interpreted executables, and 160 kernel modules, with no
unresolved symbols reported. These remain offline checks, not a hardware retest.
Only the pure-UBI format is proposed for the two-version release collection;
the CFEROM variant is not a routine-upgrade recommendation.

## Validation status

The locally generated build passed host consent/applet/UI tests, portable
validation tests with AddressSanitizer/UBSan, and an offline Chromium smoke test
against the packaged UI with a mocked backend. Static checks covered both image
CRCs and UBI/UBIFS contents, selected packaged files, dependency/symbol names for
257 executables from a 763-ELF inventory, and symbol names/vermagic for 160
kernel modules. Those results do not prove complete ABI compatibility,
exploitability resistance, hardware boot, updater compatibility or recovery.

The maintainer reported successful boot/web access, WAN/LAN networking, both
Wi-Fi bands and reboot persistence on a router. These reports were not
independently observed; the exact flashed image variant and flashing method
have not yet been recorded. Treat them as limited smoke-test reports, not an
installation guide or a guarantee for another device.

Host regression tests and the offline audit tool are documented in
[`tests/ax56u/README.md`](../tests/ax56u/README.md). These source changes do not
publish a firmware binary, raw build logs, toolchains or local verification data.
